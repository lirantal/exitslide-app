# ExitSlide production cutover

Completed on 21 November 2026. See the [verified outcome](../pilot.md#production-cutover-verification) and use the [production deployment runbook](../admin.md) for subsequent releases. The checklist below records the one-time cutover.

ExitSlide will have one deployed environment for the pilot. Run development and fixture-based tests locally. Keep GitHub Actions for verification and live smoke testing, and deploy manually with the pinned `cf` CLI. The [first GitHub staging smoke](https://github.com/lirantal/exitslide-app/actions/runs/44904227187) establishes the baseline for the cutover.

## 1. Inventory the pilot resources

- Use `pnpm exec cf auth login` in the project and complete device approval if needed. Confirm the account with `pnpm exec cf auth whoami`. Inspect only ExitSlide's Workers, their versions and bindings, and the D1 database they use. Check whether Workers Builds is connected to `main` so merges cannot unexpectedly deploy during the cutover.
- Check whether `exitslide-backend` and `exitslide-frontend` are available. The planned public origin is `https://exitslide-frontend.brain-labs.workers.dev`. Check whether anyone relies on existing Session links and capture a known link for verification if one exists.
- Confirm the current D1 UUID, migration history, and whether it contains pilot Sessions or ratings. Check the WorkOS application by client ID, including the current callback, initiate-login URL, default sign-out URL, and hosted sign-up settings. D1 stores WorkOS `user_…` IDs as Session owners. Preserve the current identity tenant if suitable for the pilot. If moving to a WorkOS production tenant is necessary, verify owner-ID mapping and existing speaker access before accepting the cutover. The current smoke helper accepts `sk_test_` keys only. Verify the production tenant's test-user provisioning, sign-in, and cleanup before enabling the workflow against it.

## 2. Prepare the repository and Actions changes

- Update both `cloudflare.config.ts` files and package deploy scripts to use the unsuffixed Worker names and one release configuration. Keep the backend private, keep preview URLs off, preserve the frontend's logging and tracing settings, and retain the live rate-limit configuration. Preserve the temporary local D1 binding for development, builds, and Verify. Make a release build require the intended remote D1 UUID before deploying with `--no-provision`.
- Rename the live Playwright suite, config, and script to use `live` terminology, including `pnpm test:e2e:live`. Use `EXITSLIDE_LIVE_URL` and `EXITSLIDE_WORKOS_SMOKE_API_KEY`. Update the URL guard to allow the intended HTTPS ExitSlide origin. Preserve temporary-user and Session cleanup, sanitized errors, and disabled trace, screenshot, and video capture. Verify that the key belongs to the AuthKit environment serving that origin.
- Replace `Staging smoke` with a manually dispatched `Live smoke` workflow restricted to `main`. Remove the `staging` environment binding and deployment-status trigger. The user adds `EXITSLIDE_WORKOS_SMOKE_API_KEY` as a repository Actions secret and can set `EXITSLIDE_LIVE_URL` as a repository Actions variable if needed. Keep the secret scoped to the Playwright step and leave Verify credential-free. Keep the old secret available until the new run succeeds.
- Update the README, architecture guide, admin instructions, pilot checklist, and WorkOS runbook. Keep the original v1 plan and staging smoke record as release history. Run lint, typecheck, Vitest, both builds, and local Playwright. Inspect the release build configuration for the remote D1 target and the frontend-to-backend service binding.

## 3. Cut over manually in Cloudflare and WorkOS

1. **D1.** Protect the current data and migration history before changing bindings. Prefer retaining the existing UUID if the database can be renamed in place. The pinned CLI's D1 edit schema currently exposes only read-replication settings. If the physical name must change and Cloudflare has no supported in-place rename, plan a copy to `exitslide` in a write-free window. Verify Session IDs, owners, ratings, and migration history before applying pending migrations to the target. Keep the source database available for recovery.
2. **Backend.** Deploy `exitslide-backend` against the verified D1 UUID with `cf` and confirm that its public and preview endpoints are disabled.
3. **Frontend.** Register the new WorkOS callback, deploy `exitslide-frontend` with the new redirect URI and private runtime secrets, and verify `/healthz`. Switch the WorkOS initiate-login URI and default sign-out URI to the new origin for the cutover. Check hosted sign-in and one-click sign-out. A hostname change requires speakers to sign in again.
4. **Existing links.** If public Session links were shared, serve their existing `/s/*` paths on the old hostname with a temporary redirect that preserves path and query. Verify that a known link reaches the same Session and that a retired link still fails. Keep the old hostname as a redirect for as long as those links need to work. Confirm link usage before removing it.

## 4. Verify, retire, or roll back

- Dispatch `Live smoke` on `main` after the release. Confirm it covers hosted sign-in, owner-only access, anonymous ratings, Session retirement, and sign-out. Verify an existing speaker can see their Sessions if the pilot already has users. Record the successful run in [pilot verification](../pilot.md).
- After verification, remove the old GitHub environment and secret, retire the old backend and any superseded D1 resource after the recovery window, and remove obsolete WorkOS entries. Keep any redirect required for previously shared links. Request confirmation before deleting the old resources.
- If cutover fails, restore the previous frontend and WorkOS login and sign-out settings. Use the previous compatible Worker versions and keep new writes on the authoritative D1 database. If a D1 copy was used and the target has accepted writes, account for those writes before routing traffic back. Rerun `/healthz` and smoke after rollback. [Worker rollback commands](../pilot.md#restore-a-prior-worker-version)
